# [PR 29](https://github.com/gerchowl/watcher-s1/pull/29) fix: MCP stop via a watcher control socket; state-file safety and resource bounds

Part of #26 (release review B1, B2, B4, B5, B6, S1, S3, S4, S5, S6 MCP tests, N1). Stacked on #27; review the last two commits.

- Hidden `--control PATH`: the watcher owns a 0600 Unix socket (`status`, `stop`). `watch_stop`/status/liveness talk only to it, with no PID or PGID signalling from files and no `ps`. A stop runs the `--timeout` escalation, including the pre-reap group SIGKILL, so TERM-ignoring descendants die. New final reason `stopped`.
- State safety: the directory-entry id is authoritative, paths derive from the run dir, `O_NOFOLLOW` and regular files only, atomic cursor writes, per-run `flock` cursor transactions.
- No blocking on the MCP runtime thread; bounded lines (1 MiB), polls (4 MiB), replies (100 events / 256 KiB, `more`), parent map (4096).
- Runs are recorded before launch; hourly pruning; rotation is checked every 500 ms.
- Not done: a per-run output cap (documented; `RLIMIT_FSIZE` would also cap the job's own files).
