# [PR 23](https://github.com/gerchowl/watcher-s1/pull/23) chore: pin the devkit flake input to 1.18.0

devkit's policy (docs/NIX.md, "versioning & release policy") says consumers
pin a release tag and bump deliberately; tracking main is not a documented
consumption mode. Pin vigos to `?ref=1.18.0`, matching DEVKIT_VERSION in
.vig-os (CI's resolve-toolchain fails a pin that lags it), and re-lock to the
tag's commit.

Set DEVKIT_FLAKE_PIN_ADVANCE=true so `install.sh --force` upgrades rewrite
the pin and flake.lock together instead of leaving the pin behind.
